# Xero MCP coverage — roadmap & decisions

**Date:** 2026-06-07
**Context:** Identifying Xero API functionality not yet surfaced by this MCP server that would
reduce manual browser work in Nestegg bookkeeping, and deciding what to build.

## Background

The server is a **thin wrapper** over the `xero-node` SDK: each tool maps ~1:1 to an SDK call
and returns raw results (e.g. report tools return the raw `ReportWithRow` rows with no
post-processing). The SDK exposes the entire Xero API surface (`accountingApi`, payroll,
`filesApi`, `assetApi`, `projectApi`, `bankFeedsApi`, `financeApi`); the MCP wires up only a
slice of `accountingApi` plus part of UK payroll.

**Auth constraint:** this is a Custom Connections (machine-to-machine) app. Requested OAuth
scopes (`src/clients/xero-client.ts`) are `accounting.*` + `payroll.*` only. Surfacing Files /
Assets / Projects would require **adding scopes**; Bank Feeds and Finance API are not available
to Custom Connections apps.

## Guiding principle

Keep the MCP a **thin, generic wrapper**. Business-specific composition (e.g. combining several
property tracking codes into an "NRPL" figure) is **Nestegg domain logic** and belongs in the
business workspace — built as separate deterministic tooling that *calls* the MCP — not inside
this server. This keeps tools upstreamable and avoids token-driven arithmetic on financial data.

## Explicitly dropped / out of scope

- **Bank transfers with tracking.** Tracked transfers are a *reconciliation-screen* feature only.
  The `BankTransfer` API object has **no tracking** (confirmed in SDK + Xero developer forum);
  the `SPEND-TRANSFER`/`RECEIVE-TRANSFER` bank-transaction types that carry tracking are
  **read-only** (generated by Xero, not POST-able); and there is **no reconciliation API**. Since
  the user creates these during reconciliation anyway, automation saves little. Dropped.
- **Custom report layouts.** The Accounting API has no endpoint to fetch a report-builder /
  advisor custom report by name. The closest is the `standardLayout=false` flag, which returns
  the standard P&L/Balance Sheet using the org's customised layout of *that standard report* —
  not a separate named report. The Nestegg NRPL/NRL reports are custom layouts and are not
  API-retrievable; filtering the standard reports by tracking is the accepted substitute.
- **Deterministic multi-option aggregation** (combining N tracking options into one P&L total).
  Belongs in business-workspace tooling, not the MCP (see Guiding principle).

## Notable gaps not (yet) queued

Bank reconciliation has **no API** (UI-only). Other unsurfaced areas: purchase orders, payment
delete/reverse, contact-group management, tax-rate create, the read-only Journals endpoint,
additional reports (Bank Summary, Executive Summary, Budget Summary), budgets, currencies,
branding themes, and most of payroll beyond timesheets/leave listing.
